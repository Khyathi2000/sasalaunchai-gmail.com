# Adding a new agent

Walks through adding a 41st agent in roughly 30 minutes. We'll use **AWS Bedrock** as the running example.

## Prereqs
- Repo cloned, `npm install` and `cd web && npm install` done
- Terraform on PATH
- A working `npm run web` at `localhost:3000`

## 1. Create the agent class

Copy the template:

```bash
cp src/agents/agents/_template-agent.ts src/agents/agents/bedrock-agent.ts
```

Rename the class. Implement `provision()` — write a Terraform file, publish outputs:

```ts
// src/agents/agents/bedrock-agent.ts
import { writeFileSync } from "fs";
import { join } from "path";
import { DeploymentAgent } from "../agent-base.js";

export class BedrockAgent extends DeploymentAgent {
  protected async provision(): Promise<void> {
    const projectName = this.getProjectName();
    const cfg = this.context.recommendation.config as { modelId?: string };
    const modelId = cfg.modelId ?? "anthropic.claude-3-haiku-20240307-v1:0";

    const tf = `# Bedrock Model Access — Generated by Launch Platform
resource "aws_bedrock_model_invocation_logging_configuration" "main" {
  logging_config {
    cloudwatch_config {
      log_group_name = aws_cloudwatch_log_group.bedrock.name
      role_arn       = aws_iam_role.bedrock.arn
    }
  }
}

resource "aws_cloudwatch_log_group" "bedrock" {
  name              = "/aws/bedrock/${projectName}"
  retention_in_days = 7
}

resource "aws_iam_role" "bedrock" {
  name = "${projectName}-bedrock-logs"
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = { Service = "bedrock.amazonaws.com" }
      Action    = "sts:AssumeRole"
    }]
  })
}

output "model_id"      { value = "${modelId}" }
output "log_group_name" { value = aws_cloudwatch_log_group.bedrock.name }
`;

    writeFileSync(join(this.context.artifactDir, "main.tf"), tf);
    this.publishOutput("modelId", modelId);
    this.publishOutput("logGroupName", "${aws_cloudwatch_log_group.bedrock.name}");
  }

  protected async configure(): Promise<void> { this.log("Bedrock configured"); }
  protected async deploy(): Promise<void>   { this.log("Bedrock deploys via terraform"); }
  protected async validate(): Promise<void> { this.log("Bedrock model accessible"); }
  protected async doRollback(): Promise<void> { this.log("Bedrock rollback"); }
}
```

**Key points:**
- Use `this.waitFor("upstream", "outputKey")` to block on dependencies. Only declare deps in `dependsOn` if you genuinely need an upstream resource's ID.
- Publish outputs as Terraform interpolation strings (`"${aws_xxx.main.id}"`) — they resolve at apply time when the orchestrator merges all .tf files into one stack.
- Read `this.context.recommendation.config.*` for user-overridable knobs.

## 2. Register in the agent factory

Edit `src/agents/agent-registry.ts`:

```ts
import { BedrockAgent } from "./agents/bedrock-agent.js";

const awsAgentMap: Record<string, AgentConstructor> = {
  // ... existing ...
  bedrock: BedrockAgent,
};
```

## 3. Add an inference rule

Either extend an existing rule or create a new file. For Bedrock, `ml.ts` is the right place:

```ts
// src/inference/rules/ml.ts (extend)
export function inferMLServices(codebase, provider) {
  // ... existing Vertex AI logic ...

  if (provider === "aws" && (hasAnthropic || hasOpenAi || hasLangchain)) {
    recs.push({
      serviceId: "bedrock",
      serviceName: "Bedrock",
      category: "ml",
      provider: "aws",
      reason: "LLM SDK detected — Bedrock for managed inference",
      confidence: hasAnthropic ? "high" : "medium",
      config: {},
      dependsOn: [],
    });
  }
  return recs;
}
```

The engine already calls `inferMLServices` (see `src/inference/inference-engine.ts:inferServices`).

## 5. Verify

Typecheck:
```
npm run typecheck
npm run web:typecheck
```

Smoke test (writes the Terraform, runs `terraform validate` in artifact mode):
```
npm run smoke -- --agent bedrock
```

End-to-end:
```
npm run web
```
Paste a repo using `@anthropic-ai/sdk` → confirm Bedrock appears in the service grid under `[ ml ]` with the right confidence and cost.

## Patterns to follow
- **Don't hardcode** values that block real deployments (instance types, region-specific AMIs, credentials). Use config knobs.
- **Pin provider versions** — happens automatically in `provider.tf` (aws ~> 5.0, google ~> 5.0).
- **Stop / start** — only override if your service supports a true pause (Lambda concurrency=0, App Runner pause). Otherwise leave default ("unsupported, use destroy").
- **Cross-references** — only `waitFor` outputs you actually need. The orchestrator's topo sort guarantees ordering; `waitFor` just blocks until the upstream agent has emitted that specific value.

## Pitfalls
- **Forgetting to register** — agent compiles fine but factory returns null and the inference engine just logs "no agent for serviceId". Always add to the registry.
- **Wrong `dependsOn`** — too few = race conditions; too many = forced serialization. Match what your TF actually references.
- **Literal vs interpolation outputs** — publish `"${aws_xxx.main.id}"` (interpolation), not the literal value. The merged stack resolves at apply time.

When in doubt, copy the closest existing agent: `vpc-agent.ts` for foundational, `rds-agent.ts` for stateful, `lambda-agent.ts` for serverless, `dynamodb-agent.ts` for data stores with rich config.
